# RFC-001: 金融计算的 Decimal 类型

| 字段 | 值 |
|------|-----|
| **状态** | 已采纳 |
| **创建日期** | 2024-12-31 |
| **作者** | - |

## 问题

金融计算需要精确的精度。浮点数（`f64`）有固有的精度问题：

```zig
const price: f64 = 0.65;
const size: f64 = 100.0;
const total = price * size;  // 可能是 64.99999999... 而不是 65.00
```

这对于交易 SDK 来说是不可接受的，因为每一分钱都很重要。

## 需求

1. 精确的十进制算术（无浮点误差）
2. 支持最多 18 位小数（以太坊标准）
3. 从字符串解析：`"0.65"`, `"-123.456"`
4. JSON 序列化为带引号的字符串
5. 零成本比较操作
6. 无外部依赖

## 提案

使用定点表示：`mantissa * 10^(-scale)`

```zig
pub const Decimal = struct {
    mantissa: i128,  // 有符号以支持负数
    scale: u8,       // 小数位数 (0-18)
};
```

### 示例

| 值 | mantissa | scale |
|----|----------|-------|
| `0.65` | 65 | 2 |
| `100` | 100 | 0 |
| `-0.001` | -1 | 3 |
| `123.456789` | 123456789 | 6 |

### API

```zig
// 创建
const d = try Decimal.fromString("0.65");
const d = Decimal.fromInt(100);

// 算术
const sum = a.add(b);
const diff = a.sub(b);
const product = a.mul(b);
const quotient = try a.div(b);

// 比较
if (a.lessThan(b)) { ... }
if (a.equal(b)) { ... }

// 输出
std.debug.print("{}", .{d});  // "0.65"
const json = d.jsonStringify(...);  // "\"0.65\""
```

## 备选方案

### 备选方案 1：使用 `f128`

**优点**: 简单，内置类型
**缺点**: 仍有精度问题，只是更少见

**决定**: 拒绝 - 精度误差不可接受

### 备选方案 2：外部库（如 GMP）

**优点**: 久经考验，任意精度
**缺点**: 外部依赖，复杂，更大的二进制文件

**决定**: 拒绝 - 我们只需要 18 位小数，不需要任意精度

### 备选方案 3：使用 i64 的定点

**优点**: 更简单，更快
**缺点**: 范围有限（使用 18 位小数时最大约 920 亿亿）

**决定**: 拒绝 - i128 提供足够的范围而无性能损失

## 决定

**使用 i128 mantissa + u8 scale**，因为：

1. 对于任何实际的金融值都没有精度损失
2. 无外部依赖
3. 实现简单
4. 对所有用例范围足够

## 实现注意事项

- 使用 `@divTrunc` 进行除法以匹配标准金融舍入
- 操作后规范化以移除尾随零
- JSON 格式：始终使用带引号的字符串以保持精度
- Scale 限制为 18 (MAX_SCALE) 以防止溢出
